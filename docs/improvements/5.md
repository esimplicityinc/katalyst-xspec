# Improvement #5: Partial Test Generation

## Status: Deferred

This improvement was considered but deferred from the initial implementation. This document provides a detailed specification for future implementation.

---

## Problem Statement

When using `playwright-bdd`, running `bddgen` (the test generation command) fails completely when any step definitions are missing. This means:

1. **No tests are generated** - even features with all steps defined don't get test files
2. **No `.features-gen/` directory is created** - blocking any test execution
3. **All-or-nothing workflow** - users must implement ALL steps before running ANY tests

### Example Scenario

```
stack-tests/
├── features/
│   ├── api/
│   │   ├── users.feature      # 10 steps, all defined ✓
│   │   └── payments.feature   # 15 steps, 5 missing ✗
│   └── ui/
│       └── login.feature      # 8 steps, all defined ✓
```

**Current behavior:**
```bash
$ npm run gen
Missing step definitions: 5
# Exit code 1, no files generated
```

**Desired behavior:**
```bash
$ npm run gen:partial
Generated tests for 2/3 features:
  ✓ features/api/users.feature
  ✓ features/ui/login.feature
  ⏭ features/api/payments.feature (5 missing steps)

Run: npm test -- --project=api --grep="users"
```

---

## Why This Matters

### BDD Workflow Benefits

Behavior-Driven Development is meant to be iterative:

1. **Write feature file** - Define desired behavior
2. **Run generator** - See what steps are needed
3. **Implement steps incrementally** - One scenario at a time
4. **Run tests as you go** - Verify each implementation

Without partial generation, this workflow breaks down because you can't run any tests until everything is complete.

### Real-World Impact (from ClawMarket experience)

> "bddgen ran successfully but showed warnings: Missing step definitions: 1533"
>
> "bddgen doesn't create output when steps are missing"
>
> "The feature files contain 1533 step usages that don't have corresponding step definitions implemented yet."

With 1533 missing steps, the team couldn't run a single test until implementing all of them - a significant barrier to incremental development.

---

## Proposed Solution

### Approach 1: Pre-Filter Wrapper (Recommended)

Create a wrapper script that filters features before passing to bddgen.

```
┌─────────────────────────────────────────────────────────────┐
│                    partial-gen.js                            │
├─────────────────────────────────────────────────────────────┤
│  1. Parse all .feature files                                │
│  2. Extract step patterns (Given/When/Then)                 │
│  3. Scan registered steps from steps/*.ts                   │
│  4. Identify features with all steps defined                │
│  5. Create temp directory with only complete features       │
│  6. Run bddgen on temp directory                            │
│  7. Copy generated files to .features-gen/                  │
│  8. Report statistics                                       │
└─────────────────────────────────────────────────────────────┘
```

### Approach 2: Tag-Based Filtering

Use Gherkin tags to mark features as "ready" for generation.

```gherkin
@ready
Feature: User Authentication
  ...
```

```bash
# Only generate @ready features
npm run gen -- --tags @ready
```

**Pros:** Simple, uses existing bddgen functionality
**Cons:** Requires manual tagging, easy to forget

### Approach 3: Playwright-BDD Upstream Contribution

Contribute a `--partial` or `--skip-missing` flag to `playwright-bdd` itself.

**Pros:** Native solution, benefits entire community
**Cons:** Depends on upstream acceptance, longer timeline

## Implementation Details

### Feature Parser (`feature-parser.ts`)

```typescript
import * as fs from 'fs';
import * as path from 'path';

interface StepUsage {
  keyword: 'Given' | 'When' | 'Then' | 'And' | 'But';
  text: string;
  line: number;
  file: string;
}

interface FeatureInfo {
  file: string;
  name: string;
  scenarios: number;
  steps: StepUsage[];
}

export function parseFeatureFile(filePath: string): FeatureInfo {
  const content = fs.readFileSync(filePath, 'utf8');
  const lines = content.split('\n');
  
  const steps: StepUsage[] = [];
  let featureName = '';
  let scenarioCount = 0;
  let lastKeyword: StepUsage['keyword'] = 'Given';
  
  for (let i = 0; i < lines.length; i++) {
    const line = lines[i].trim();
    
    // Feature name
    if (line.startsWith('Feature:')) {
      featureName = line.substring(8).trim();
      continue;
    }
    
    // Scenario count
    if (line.startsWith('Scenario:') || line.startsWith('Scenario Outline:')) {
      scenarioCount++;
      continue;
    }
    
    // Step definitions
    const stepMatch = line.match(/^(Given|When|Then|And|But)\s+(.+)$/);
    if (stepMatch) {
      const keyword = stepMatch[1] as StepUsage['keyword'];
      const text = stepMatch[2];
      
      // And/But inherit from previous keyword
      const effectiveKeyword = (keyword === 'And' || keyword === 'But') 
        ? lastKeyword 
        : keyword;
      
      if (keyword !== 'And' && keyword !== 'But') {
        lastKeyword = keyword;
      }
      
      steps.push({
        keyword: effectiveKeyword,
        text,
        line: i + 1,
        file: filePath,
      });
    }
  }
  
  return {
    file: filePath,
    name: featureName,
    scenarios: scenarioCount,
    steps,
  };
}

export function findFeatureFiles(dir: string): string[] {
  const results: string[] = [];
  
  function walk(currentDir: string) {
    const entries = fs.readdirSync(currentDir, { withFileTypes: true });
    
    for (const entry of entries) {
      const fullPath = path.join(currentDir, entry.name);
      
      if (entry.isDirectory() && !entry.name.startsWith('.')) {
        walk(fullPath);
      } else if (entry.isFile() && entry.name.endsWith('.feature')) {
        results.push(fullPath);
      }
    }
  }
  
  walk(dir);
  return results;
}
```

### Step Scanner (`step-scanner.ts`)

```typescript
import * as fs from 'fs';
import * as path from 'path';

interface RegisteredStep {
  keyword: 'Given' | 'When' | 'Then';
  pattern: string | RegExp;
  file: string;
  line: number;
}

export function scanStepFiles(stepsDir: string): RegisteredStep[] {
  const steps: RegisteredStep[] = [];
  const files = fs.readdirSync(stepsDir).filter(f => f.endsWith('.ts'));
  
  for (const file of files) {
    const filePath = path.join(stepsDir, file);
    const content = fs.readFileSync(filePath, 'utf8');
    
    // Match step definitions: Given('pattern', ...) or Given(/regex/, ...)
    const stepRegex = /(Given|When|Then)\s*\(\s*(['"`]([^'"`]+)['"`]|\/([^/]+)\/)/g;
    let match;
    
    while ((match = stepRegex.exec(content)) !== null) {
      const keyword = match[1] as RegisteredStep['keyword'];
      const pattern = match[3] || match[4]; // String or regex pattern
      
      // Calculate line number
      const beforeMatch = content.substring(0, match.index);
      const line = beforeMatch.split('\n').length;
      
      steps.push({
        keyword,
        pattern: match[4] ? new RegExp(match[4]) : pattern,
        file: filePath,
        line,
      });
    }
  }
  
  return steps;
}

export function stepMatches(
  stepText: string, 
  registeredStep: RegisteredStep
): boolean {
  const pattern = registeredStep.pattern;
  
  if (pattern instanceof RegExp) {
    return pattern.test(stepText);
  }
  
  // Convert Cucumber expression to regex
  // {string} -> "[^"]*" or '[^']*'
  // {int} -> -?\d+
  // {float} -> -?\d+\.?\d*
  // {word} -> \S+
  // {} -> .*
  const regexPattern = pattern
    .replace(/\{string\}/g, '(?:"[^"]*"|\'[^\']*\')')
    .replace(/\{int\}/g, '-?\\d+')
    .replace(/\{float\}/g, '-?\\d+\\.?\\d*')
    .replace(/\{word\}/g, '\\S+')
    .replace(/\{\}/g, '.*')
    .replace(/\{[^}]+\}/g, '.*'); // Any other parameter
  
  const regex = new RegExp(`^${regexPattern}$`);
  return regex.test(stepText);
}
```

### Main Script (`partial-gen.js`)

```javascript
#!/usr/bin/env node
'use strict';

const { execSync, spawnSync } = require('child_process');
const fs = require('fs');
const path = require('path');
const os = require('os');

// Import parsers (would be compiled from TypeScript)

function parseArgs(args) {
  return {
    verbose: args.includes('--verbose') || args.includes('-v'),
    strict: args.includes('--strict'),
    list: args.includes('--list'),
    help: args.includes('--help') || args.includes('-h'),
  };
}

function showHelp() {
  console.log(`
Usage: npx partial-gen [options]

Generate Playwright-BDD tests only for features with all steps defined.

Options:
  -v, --verbose  Show detailed information about skipped features
  --strict       Exit with error if any features are skipped
  --list         List feature status without generating
  -h, --help     Show this help message

Examples:
  npx partial-gen              # Generate complete features
  npx partial-gen --verbose    # Show why features are skipped
  npx partial-gen --list       # Just show status, don't generate
`);
}

async function main() {
  const args = parseArgs(process.argv.slice(2));
  
  if (args.help) {
    showHelp();
    process.exit(0);
  }
  
  console.log('Partial Generation Report');
  console.log('═'.repeat(60));
  console.log('');
  
  // 1. Find all feature files
  console.log('Scanning features...');
  const featuresDir = path.join(process.cwd(), 'features');
  const featureFiles = findFeatureFiles(featuresDir);
  
  // 2. Parse each feature
  const features = featureFiles.map(f => parseFeatureFile(f));
  const totalScenarios = features.reduce((sum, f) => sum + f.scenarios, 0);
  console.log(`  Found ${features.length} feature files with ${totalScenarios} scenarios`);
  console.log('');
  
  // 3. Scan registered steps
  console.log('Checking step definitions...');
  const stepsDir = path.join(process.cwd(), 'features', 'steps');
  const registeredSteps = scanStepFiles(stepsDir);
  console.log(`  Found ${registeredSteps.length} registered steps`);
  console.log('');
  
  // 4. Check each feature for completeness
  const ready = [];
  const skipped = [];
  
  for (const feature of features) {
    const missingSteps = [];
    
    for (const step of feature.steps) {
      const hasMatch = registeredSteps.some(rs => 
        rs.keyword === step.keyword && stepMatches(step.text, rs)
      );
      
      if (!hasMatch) {
        missingSteps.push(step);
      }
    }
    
    if (missingSteps.length === 0) {
      ready.push(feature);
    } else {
      skipped.push({ feature, missingSteps });
    }
  }
  
  // 5. Report results
  const readyScenarios = ready.reduce((sum, f) => sum + f.scenarios, 0);
  const skippedScenarios = skipped.reduce((sum, s) => sum + s.feature.scenarios, 0);
  
  console.log('Results:');
  console.log(`  ✓ ${ready.length} features ready (${readyScenarios} scenarios)`);
  console.log(`  ⏭ ${skipped.length} features skipped (${skippedScenarios} scenarios)`);
  console.log('');
  
  if (args.verbose && skipped.length > 0) {
    console.log('Skipped Features:');
    for (const { feature, missingSteps } of skipped) {
      console.log(`  ${path.relative(process.cwd(), feature.file)}`);
      const uniqueMissing = [...new Set(missingSteps.map(s => `${s.keyword} ${s.text}`))];
      for (const step of uniqueMissing.slice(0, 5)) {
        console.log(`    Missing: ${step}`);
      }
      if (uniqueMissing.length > 5) {
        console.log(`    ... and ${uniqueMissing.length - 5} more`);
      }
      console.log('');
    }
  }
  
  // 6. Generate if not list-only
  if (!args.list && ready.length > 0) {
    console.log('Generating tests for ready features...');
    
    // Create temp directory with only ready features
    const tempDir = fs.mkdtempSync(path.join(os.tmpdir(), 'partial-gen-'));
    const tempFeaturesDir = path.join(tempDir, 'features');
    
    // Copy ready features maintaining directory structure
    for (const feature of ready) {
      const relPath = path.relative(featuresDir, feature.file);
      const destPath = path.join(tempFeaturesDir, relPath);
      fs.mkdirSync(path.dirname(destPath), { recursive: true });
      fs.copyFileSync(feature.file, destPath);
    }
    
    // Copy steps directory
    const tempStepsDir = path.join(tempFeaturesDir, 'steps');
    fs.cpSync(stepsDir, tempStepsDir, { recursive: true });
    
    // Run bddgen on temp directory
    // Note: This would need playwright config modification
    // For now, show what would be generated
    
    for (const feature of ready) {
      const relPath = path.relative(featuresDir, feature.file);
      console.log(`  Would generate: .features-gen/${relPath.replace('.feature', '.spec.js')}`);
    }
    
    // Cleanup
    fs.rmSync(tempDir, { recursive: true, force: true });
  }
  
  // 7. Summary
  console.log('');
  console.log('═'.repeat(60));
  const percentage = Math.round((ready.length / features.length) * 100);
  console.log(`Summary: ${ready.length}/${features.length} features ready (${percentage}%)`);
  
  if (ready.length < features.length) {
    console.log('');
    console.log('Next steps:');
    console.log('  1. Run available tests: npm test');
    console.log('  2. Implement missing steps (run with --verbose to see list)');
    console.log('  3. Re-run: npm run gen:partial');
  }
  
  // 8. Exit code
  if (args.strict && skipped.length > 0) {
    process.exit(1);
  }
}
```

## Challenges and Considerations

### 1. Step Pattern Matching Complexity

Cucumber expressions support various parameter types:
- `{string}` - Quoted strings
- `{int}` - Integers
- `{float}` - Floating point numbers
- `{word}` - Single word
- `{}` - Anonymous (any)
- Custom types

The matcher needs to handle all these cases correctly.

### 2. Steps from Library

Steps registered via `registerApiSteps(test)` etc. from `@esimplicity/stack-tests` won't be in the local `steps/` directory. The scanner needs to:
1. Parse import statements
2. Resolve to node_modules
3. Scan library step definitions

### 3. Playwright-BDD Integration

Running bddgen on a subset of features requires either:
1. Modifying `playwright.config.ts` temporarily
2. Using bddgen's `--features` flag (if available)
3. Creating a temp config file

### 4. Generated Test Output

The `.features-gen/` directory structure needs to match the original feature structure, even when only generating partial features.
